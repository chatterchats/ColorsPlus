# Databank entry crash, 2026-09-15

Crash directory: `UECC-Windows-A93A1139470A7523314D0A8DD54990E2_0000`
under the supplied game's `Saved/Crashes` directory.

## Evidence

- The report records a GameThread access violation reading `0x10`, 18 seconds
  after launch, with the first reported frame at `UE4SS.dll+0x270717`.
- The installed UE4SS version identifies Git SHA `a1e7f571`.
- Disassembly at that address is `mov r8, [rax]`, immediately following a call
  to the exact exported function `UObjectBase::GetClassPrivate` at RVA
  `0x3a1810`. This is consistent with class access through a null UObject.
  Other frame names were not resolved; nearest exports alone are not reliable
  symbols for those frames.
- The final application log message is Character Share starting its bounded
  Databank entry check at `12:27:05 UTC`.
- Colors+Probe installed its hooks at `12:26:57 UTC`. It emitted no snapshot
  or session-end message before the crash. This alone does not exclude the
  probe because snapshots are formatted before their BEGIN message is written.

## Concrete defect found

Character Share's entry check calls `find_live_databank_master`, which gets the
master through `FindFirstOf` and passes it to `object_class_full_name`.
That helper checked only for nil before calling `GetClass`.
UE4SS can return an invalid, non-nil UObject wrapper when an instance is not
available. The class-access fault and log timing strongly fit this path, but
the dump does not identify the originating Lua source line conclusively.

## Correction and checks

Added validity checks before `GetClass` and before the returned class's
`GetFullName` in Character Share's source and matching installed copy.
Colors+Probe's behavior was not changed as part of this correction.

The new Character Share discovery regression reproduced the missing guard
before the change, then passed after it. It covers nil, an invalid wrapper, an
exception during validity lookup, an invalid class, and a valid attached master.
Character Share's existing module bootstrap/reload and widget adoption tests
also passed.

not a conclusively resolved in-game crash. If it repeats, compare the new fault
and logs; do not assume a matching user-visible trigger has the same cause.
